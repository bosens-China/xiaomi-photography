# 每周云端更新

- 基线：[现行产品需求](../../PRD.md)
- 依赖：当前 Astro 迁移、周刊 JSON 和新版部署工作流先发布到远端 `main`；部署工作流启用并验证成功；用户在 ChatGPT 创建具备网页读取和 GitHub 写入能力的云端任务。

## 背景与目标

通过 ChatGPT 云端任务检查小米官方获奖作品的实际变化，更新仓库 JSON，再由现有 CI 构建发布。不依赖本机开机，也不按周复制没有变化的年度获奖集。

## 已确认的增量需求

- 用户自行创建任务；每周一北京时间 08:00，时区 `Asia/Shanghai`。
- 官方来源和中国摄影师作品的范围沿用当前画廊。与全部归档比较，避免重复收录和无内容变化的提交。
- 确认新增作品时发布仅含增量作品的新一期；官方更正已有作品时修正原记录，保留日期和 id。抓取失败或内容暂时缺失不删除历史数据。
- 云端任务只写入 `src/data/issues/*.json`，验证后向 `main` 提交；CI 继续负责静态构建和 GitHub Pages 发布。
- 每次检查部署工作流状态；推送后追踪本次提交的构建、部署和线上内容。内容变化、失败或需要用户处理时提醒。

## 范围与非目标

使用 ChatGPT 云端定时任务，不新增 GitHub Actions 定时抓取、不创建 Codex 本地自动化，不在本轮替用户创建云端任务。任务不修改应用代码、工作流、依赖或仓库设置。

## 验收标准

- 创建后的任务界面显示每周一北京时间 08:00，并能访问网页和目标仓库。
- 无变化时不创建新期、不产生提交；抓取失败时保留全部原数据。
- JSON 符合仓库约定，新增与更正均正确去重，重复执行不产生重复内容。
- 内容变化的提交只包含周刊 JSON，匹配提交 SHA 的 `build` 和 `deploy` 成功，线上内容可验证。
- 无权限、工作流停用、构建失败、未触发或未完成的部署有明确报告。

## 对后续计划的影响

任务实际启用并完成端到端验收后，再将长期行为合并到现行 PRD。创建指令、JSON 示例和 CI 检查方法统一维护在[每周云端更新任务](../../weekly-update-task.md)。
