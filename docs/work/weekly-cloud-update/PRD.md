# 每周 CI 更新

- 基线：[现行产品需求](../../PRD.md)
- 依赖：GitHub Actions 和 Pages 已启用，自动更新任务具备提交周刊 JSON 的权限。

## 背景与目标

由 GitHub Actions 每周检查小米国内和国际官方获奖来源，更新仓库 JSON，再构建并发布。不依赖本机或 ChatGPT 定时任务，也不按周复制没有变化的年度获奖集。

## 已确认的增量需求

- CI 每周一北京时间 07:00（`Asia/Shanghai`）计划执行，并支持手动运行。
- 检查国内和国际官方获奖页，维护国内、国际两版 JSON。国内、国际按官网来源划分，各自收录完整具名作品，不按摄影师国籍过滤。两版独立识别赛事年份，允许跨版作品重叠；同一版、同一届内与历史归档比较，避免重复抓取产生重复记录。国内与国际统一使用有图画廊和详情查看器，既有外链名单在原期次内补齐原图、实际尺寸和作品说明，保留既有照片链接。
- 确认新增作品时发布仅含增量作品的新一期；官方更正已有作品的标题、署名和非空说明时修正原记录，保留日期和 id；已有图片地址与尺寸仍需人工核实后维护。抓取失败或内容暂时缺失不删除历史数据。
- 抓取程序只更新 `src/data/issues/*.json`；有变化时先完成 JSON 校验和构建，成功后提交到 `main` 并发布对应内容。
- 抓取、构建、提交和部署须形成完整流程，不能依赖机器人推送自动触发另一次 `push` 工作流。失败须在 Actions 中明确呈现，不发布未经验证的数据。

## 范围与非目标

使用 GitHub Actions 定时抓取、仓库 JSON 和 GitHub Pages；不创建 ChatGPT 或 Codex 定时任务。图片展示按本轮用户确认的统一看图方式更新[现行产品需求](../../PRD.md)。本轮实施抓取程序和工作流，并完成本地验证；远端启用和发布需在推送后验收。

## 验收标准

- 工作流配置每周一北京时间 07:00，并支持手动验证同一抓取流程。
- 国内和国际来源均可读取，正确维护 `YYYY-MM-DD.json` 与 `YYYY-MM-DD-international.json`，保留既有有图版和作品链接，旧外链版原期补图，新增作品生成有图版，支持另一版无新增时的空期。
- 无变化时不创建新期、不产生提交；抓取失败时保留全部原数据。
- JSON 符合仓库约定，新增与更正在各自版本内正确匹配，跨版重叠作品两边均保留，重复执行不新增重复记录。
- 内容变化的提交只包含周刊 JSON；构建产物与提交内容一致，构建、提交和部署均成功，线上内容可验证。
- 无权限、工作流停用、构建失败、未触发或未完成的部署有明确报告。

## 对后续计划的影响

工作流实际启用并完成端到端验收后，再将长期行为合并到现行 PRD。流程和待补环节见[每周 CI 更新任务](../../weekly-update-task.md)。

## 当前进度

本地已完成两版真实抓取、旧名单补图、JSON 更新与重复运行验证（按官网来源独立收录），并使用内置浏览器核查窄屏画廊、照片详情、构图工具、切图和返回滚动位置。真实手机的双指触控尚未验收，脚本类型检查、Lint、自动化测试及静态构建通过。远端定时执行、机器人提交权限和 Pages 部署尚待推送后验收，需求继续保留在进行中。
